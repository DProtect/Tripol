# Build and architecture

Go 1.23+ is required for contributors rebuilding the compiler, not for users of distributed binaries. On a supported x86-64 host:

```sh
go test -count=1 -v .
go vet .
CGO_ENABLED=0 go build -trimpath -ldflags='-s -w' -o tripol .
mkdir -p installer/payload
cp examples/hello.tri installer/payload/hello.tri
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o installer/payload/tripol.exe .
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o TRIPOL-v0.12-Setup-x64.exe ./installer
```

The installer is unsigned, installs under `%LOCALAPPDATA%\Programs\TRIPOL`, uses PowerShell to update user PATH, and supports `--quiet` and `--uninstall`. Close and reopen CMD. Linux x86-64 ELF uses direct syscalls; Windows PE32+ uses OS DLLs for selected functionality. There is no external language runtime in generated executables.

`main.go` owns parser, checking and x86 emitter; feature files implement language/runtime helpers; `native/liberty.S` is maintained assembly; `liberty_code.go` contains checked-in generated byte templates. Maintainers can regenerate with `python native/generate.py` (requires GNU as/objdump/objcopy); not needed for regular compiler builds. `stdlib` is embedded; `installer` produces Windows setup. `vscode` provides syntax highlighting, not a full debugger. No TIR or self-hosting yet.

CLI: `tripol build FILE.tri --target windows|linux -o OUTPUT --profile nano|debug`, `tripol check`, `tripol run`, `tripol bench FILE.tri --runs N`, `tripol bench-build FILE.tri --runs N`. Default source main.tri, default nano; debug disables optimization, not a native debugger. Bench measures process startup and execution, one warm-up excluded, stdout discarded, stdin closed; use noninteractive programs. Bench-build measures source load and compilation excluding startup/write, checks deterministic output. No built-in timeout.

Vault: `tripol add NAME FILE.tri --version X.Y.Z`, `tripol packages`, `tripol verify`, `tripol remove NAME`. Lockfile pins version and SHA-256, cache `.tripol/packages/`; copy both for offline builds. No remote registry, scripts or semver solver; trust package code. See `vault.go` and tests for exact constraints.
