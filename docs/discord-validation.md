# Discord v0.28 live validation / Validación conectada

## Setup / Preparación

Use an app and a private test guild you are authorized to administer. Install with the `bot` and `applications.commands` scopes. Grant View Channel, Send Messages and Attach Files in the test channel. For moderation, use a dedicated test account and only the permissions being tested. Place the bot role above disposable targets, and also test one target above the bot role.

Usa una aplicación y un servidor privado de pruebas que tengas autorización para administrar. Instala el bot con los ámbitos `bot` y `applications.commands`. Concede Ver canal, Enviar mensajes y Adjuntar archivos en el canal de pruebas. Para moderación, usa una cuenta de prueba dedicada y concede solo los permisos que se comprobarán. Coloca el rol del bot por encima de los objetivos de prueba y verifica también un objetivo por encima del rol del bot.

Provide `DISCORD_TOKEN` and the numeric `DISCORD_GUILD_ID` via the process environment. Keep the token out of source files, screenshots, shell history and shared logs. Save a small local `report.txt` with known contents in the working directory. From the repository run `tripol run examples/discord_stability.tri`. On Windows also verify the compiled executable with `tripol build examples/discord_stability.tri -o stability.exe` and `tripol discord-run stability.exe`. On Linux build to `stability` and run `./stability` to exercise the bundle.

Configura `DISCORD_TOKEN` y el ID numérico `DISCORD_GUILD_ID` en el entorno del proceso. Mantén el token fuera del código, capturas, historial de la consola y registros compartidos. Guarda un `report.txt` pequeño de contenido conocido en el directorio de trabajo. Desde el repositorio ejecuta `tripol run examples/discord_stability.tri`. En Windows prueba también `tripol build examples/discord_stability.tri -o stability.exe` y `tripol discord-run stability.exe`. En Linux compila a `stability` y ejecuta `./stability` para comprobar el paquete.

## Cases and expected results / Casos y resultados esperados

| Case / Caso | Expected result / Resultado esperado |
| --- | --- |
| `/feedback` | Submit with and without choices and a file. The topic is required and the count and filename agree with the submission. Check that Discord rejects an unsupported extension when the client applies the filter. / Envíalo con y sin opciones o adjunto. El tema es obligatorio y coinciden el número de opciones y el nombre del archivo. Comprueba que Discord rechace una extensión incompatible cuando el cliente aplica el filtro. |
| `/rating` | Select each fractional choice. The private response displays the selected number. After restarting, the guild still has one command with two choices. / Selecciona cada elección decimal. La respuesta privada muestra el número seleccionado y al reiniciar sigue habiendo un comando con dos elecciones. |
| User and message context menus / Menús de usuario y mensaje | Choose **Ver usuario** on a test account and **Ver mensaje** on a test message. Check visibility as a second user. The invoker sees the selected username or the selected text in an embed. / Selecciona **Ver usuario** en una cuenta de prueba y **Ver mensaje** en un mensaje de prueba. Comprueba la visibilidad desde otra cuenta. Quien invoca recibe el nombre del usuario o el texto seleccionado en un embed. |
| Multipart / Adjuntos | Invoke `/report`. The private Components V2 File opens the bytes from `report.txt`. Rename the file and repeat, then restore it and retry as a fresh interaction. Test an embed with `attachment://` from the bilingual guide, and compare each uploaded file’s hash with its local original. / Ejecuta `/report`. El componente File privado de V2 abre los bytes de `report.txt`. Renombra el archivo y repite. Restáuralo e inicia una interacción nueva. Prueba un embed con `attachment://` de la guía bilingüe y compara el hash del archivo descargado con el local. |
| Moderation / Moderación | Create the `discord-moderation` template in an isolated directory. Set `DISCORD_OPERATOR_ID`. Verify that a different user and an operator missing the effective permission are denied. Exercise `/warn` twice with a restart between calls. Check the two entries in `discord-warnings.jsonl` and the absence of entries for denied calls. Test `/kick`, `/ban`, `/unban` and `/timeout` against disposable users, including Discord’s rejection of a target above the bot’s role. / Crea la plantilla `discord-moderation` en un directorio aislado. Configura `DISCORD_OPERATOR_ID`. Prueba el rechazo de otro usuario y del operador sin el permiso efectivo. Ejecuta `/warn` dos veces con un reinicio entre medias. Comprueba que `discord-warnings.jsonl` contiene ambas entradas y ninguna de llamadas rechazadas. Prueba los cuatro comandos de moderación con usuarios de prueba, incluido el rechazo de Discord si el rol del objetivo está por encima del bot. |
| Disconnect and recovery / Desconexión y recuperación | From a test machine or VM, interrupt connectivity briefly after READY and restore it. Verify the bot responds again and each numbered command or event is processed once. On Linux, use `tripol discord studio examples/discord_stability.tri --metrics stability.jsonl` to check `reconnects` and `resumes`. Use Ctrl+C and confirm the child exits. Restart and verify a new connection. / En una máquina de pruebas o VM interrumpe brevemente la conexión tras READY y restáurala. Comprueba que el bot vuelve a responder y procesa una vez cada comando o evento numerado. En Linux usa Studio con el comando anterior y revisa `reconnects` y `resumes`. Pulsa Ctrl+C y comprueba que termina el proceso hijo. Reinicia y verifica una conexión nueva. |

Keep the platform, commit, test case, expected and observed outcomes, and redacted diagnostics for each run. Anota plataforma, commit, resultado previsto y observado, y diagnósticos sin datos privados. Usa el servidor TLS local para provocar HTTP 429 y replay en masa sin saturar Discord. ## FINAL POLISH on Windows and Linux / FINAL POLISH en Windows y Linux

Run the following examples in a disposable private guild on both systems. Set `DISCORD_CHANNEL_ID` to a disposable text channel and `DISCORD_OPERATOR_ID` to a test operator. Grant the bot the matching permissions for each case. For hierarchy testing, configure one test member below both the bot and operator, another above either of them, and a test owner account. Keep the tests in a working directory that can store the economy ledger and cooldown data.

Ejecuta estos ejemplos en un servidor privado desechable en ambos sistemas. Usa `DISCORD_CHANNEL_ID` para un canal de texto de pruebas y `DISCORD_OPERATOR_ID` para el operador de pruebas. Concede al bot los permisos de cada caso. Para probar la jerarquía, configura un miembro por debajo del bot y del operador, otro por encima de cualquiera de ellos y una cuenta propietaria de pruebas. Ejecuta en un directorio donde se puedan guardar los puntos y cooldowns.

| Program / Programa | Cases / Casos |
| --- | --- |
| `tripol run examples/discord_economy.tri` | Invoke `/daily` twice as one user and once as another. The first and third calls add ten points to their own balance, and the second displays remaining seconds. Restart it and verify the first user remains limited and `/saldo` still shows ten. / Ejecuta `/daily` dos veces como un usuario y una vez como otro. La primera y tercera suman diez puntos a su saldo y la segunda indica los segundos restantes. Reinicia y comprueba que sigue vigente el cooldown y que `/saldo` conserva los diez puntos. |
| `tripol run examples/discord_polish.tri` with Manage Roles and Create Instant Invite / con Gestionar roles y Crear invitación | Capture the @everyone channel overwrite, run `/lock` and `/unlock` and compare the original values. Repeat with an external overwrite edit and confirm unlock refuses to replace it. Run `/invite` and use the invitation with a disposable test account. Verify it expires after one use or ten minutes. / Registra el permiso de @everyone, prueba `/lock` y `/unlock` y compara los valores. Repite con un cambio externo y comprueba que se conserva. Prueba `/invite` y verifica que la invitación caduca tras un uso o diez minutos. |
| `/ban-prueba` with Ban Members / con Banear miembros | Test without Ban Members on the operator, without it on the bot, against the owner and against the higher member. Verify that each action is denied and leaves audit logs free of a ban for those targets. Test a disposable lower-ranked account last and verify the Discord audit entry. / Prueba sin permiso para el operador, sin permiso para el bot, contra el propietario y contra el miembro superior. Comprueba que se rechazan y que no aparecen baneos para esos objetivos. Prueba al final con una cuenta inferior desechable y verifica la entrada de auditoría. |
| `tripol run examples/discord_admin_resources.tri` | First set `DISCORD_RESOURCE_TEST=webhook` with Manage Webhooks and a local `report.txt`. Verify the message, embed, non-interactive V2 layout and attachment, then deletion of the created webhook. Repeat with `thread` and thread management permissions and then with `forum` and Manage Channels. Use a test guild that supports forums. Verify each created resource's ID, edited name, archive state and cleanup. / Usa primero `DISCORD_RESOURCE_TEST=webhook`, Gestionar webhooks y un `report.txt` local. Verifica mensaje, embed, panel V2 no interactivo, adjunto y eliminación. Repite con `thread` y permisos de gestión de hilos, y con `forum` y Gestionar canales en un servidor de pruebas que admita foros. Verifica los IDs, cambios, archivado y eliminación. |

Repite los casos anteriores de desconexión, Resume y recuperación de errores y anota el pico de memoria durante una sesión larga representativa. Separa estos datos de los benchmarks locales de SDK.
